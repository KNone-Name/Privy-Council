## 0. 一句话

**从运行中的游戏里只读地读出事实 → 用纯函数算清账 → 让 LLM 在硬约束下决策 → 由注入式 DLL 或游戏内面板执行。**

整条链路分五层，每层只依赖左侧一层，可独立测试、可离线回放：

```
┌────────────┐   ┌────────────┐   ┌────────────┐   ┌────────────┐   ┌────────────┐
│  v3live    │──▶│  v3calc    │──▶│   v3ai     │──▶│  v3bridge  │──▶│  Victoria 3 │
│  内存读取   │   │  计算/算账  │   │ LLM 决策    │   │ DLL 执行    │   │   游戏进程   │
└────────────┘   └────────────┘   └────────────┘   └────────────┘   └────────────┘
       ▲                                                                    │
       │                        ┌────────────────┐                          │
       └────────────────────────│   v3panel      │◀─────────────────────────┘
                                │  游戏内 AI 面板 │  （mod + 桥 + 外部服务）
                                └────────────────┘
```

## 2. v3live —— 内存读取层（数据端）

> 13 个文件 / 约 6200 行　|　入口：python tools\v3live\run.py <命令>（或 python -m v3live）

**职责**：对运行中的 victoria3.exe 做**只读**（PROCESS_VM_READ）内存读取，把国家、预算、州、建筑、市场、人口、政治等状态读成结构化快照。

| 文件 | 职责 |
|---|---|
| cli.py（4286 行） | 全部读取命令：read / gdp / states / buildings / market / budget / pops / politics / laws / tech / decrees / institutions / companies / prices / localprices / capacity / quals / map / report / peek / dump / find / scan / static / watch / prewarm … |
| proc.py | 进程句柄、模块基址、内存读写（Native API） |
| discover.py | 进程发现、主菜单/读档状态判定（拒绝半成品数据） |
| rtti.py / static.py | RTTI 类名扫描、静态区扫描 |
| pe.py | PE 头解析、版本指纹 |
| gamedata.py | 游戏文件里的规则常量（与计算层共用口径） |
| diffscan.py | 版本更新的差分扫描 |
| verify_all.py | 端到端自检（16 项） |
| selftest.py | 自带测试 |
| _cache/（运行时生成） | 类扫描缓存，游戏重启后自动重建 |

**关键特性**
- 每次游戏重启后先 prewarm 一次（全量类扫描，本机约 2~3 分钟），之后读取走缓存（秒级）；
- 行政力、建造力与游戏界面**精确相等**；GDP 误差库有校准记录；
- 只读：不写内存、不点 UI、不改存档。

## 3. v3calc —— 计算层（算账端）

> 21 个文件 / 约 7300 行　|　入口：python v3.py <命令>　|　自带测试 34 项

**职责**：不碰内存、不碰存档，只吃「快照（事实）+ 游戏数据（规则）」，纯函数式计算，可回放、可测试、可做「如果换成 X 会怎样」的方案对比。

| 文件 | 职责 |
|---|---|
| model.py | Snapshot 数据模型（国家/预算/州/建筑/市场/法律/科技…），JSON 可序列化 |
| pdx.py | Paradox 脚本解析器（保留重复键、裸值列表、引号转义、运算符） |
| gamedata.py | GameData：商品/生产方式/生产方式组/建筑/科技/法律（从 common/*.txt 解析） |
| market.py | 价格模型 PriceModel（供给需求→价格倍率，可平移推演）、产业链聚合、缺口定价 |
| gdp.py | GDPCalculator：按建筑×PM×商品计算 GDP，支持价格基准/缩放/建筑范围 |
| construction.py | 造价（建造点）、每周建造力、州静态地理（state_meta.json） |
| candidates.py（1013 行） | 决策算账核心：可建性检查、商品向量、**五元打分**（年增值/建造点/工期/风险/链权重）、逐步贪心方案、PM 候选、Intent 策略 |
| pm.py | PMChecker：当前科技/法律/条件→生产方式是否可用（available/conditional/locked） |
| signals.py | 价格/财政/结构异常→触发信号（空=这轮不需 LLM） |
| brief.py | 一页纸简报（≤2500 字符，给 LLM 压缩后的局势） |
| ledger.py | JSONL 台账：记账→对账→偏差校准 |
| advisor.py | 门面：一次构造导出简报/市场/候选/方案/信号；quick() 纯规则快通道 |
| savefile.py | 文本存档解析（游戏没开时的离线来源） |
| worldstate.py / scenario.py | 世界状态聚合 / 情景推演 |
| fastscan.py | 并行 vtable 扫描加速 |
| live.py | 实时层适配（对接 v3live） |
| cli.py（1055 行） | 命令行：read / gdp / pm / upgrades / watch / prewarm / selftest / advise… |

**命令速查**
```bat
python v3.py read --json snap.json      :: 实时读全量快照
python v3.py gdp --by-good              :: GDP（默认：市场价+实际就业+只算生产建筑）
python v3.py pm --building building_food_industry --show-locked
python v3.py upgrades --top 20          :: 换 PM 方案（GDP 增量排序）
python -m v3calc advise brief --snapshot snap.json      :: 一页纸简报
python -m v3calc advise plan --snapshot snap.json --weeks 12
python -m v3calc advise signals --snapshot snap.json    :: 空=市况平稳
python -m v3calc advise ledger --snapshot f2.json --reconcile
```

## 4. v3ai —— 决策层（LLM 端）

> 18 个文件 / 约 7700 行　|　入口：python v3.py ai <命令>　|　Web UI：http://127.0.0.1:8765

**职责**：把「事实（快照）+ 规则（游戏文件）」拼成世界模型，让 LLM 在策略与硬约束下自主查证、提议动作；审查层挡在 LLM 与执行端之间，只放行当前条件下确实能执行的动作。

| 文件 | 职责 |
|---|---|
| agent.py（632 行） | AgentLoop 主循环：refresh→brief→LLM 工具循环→执行→记录 |
| runtime.py（470 行） | 一轮的生命周期：快照刷新、简报生成、待执行动作、执行反馈 |
| world.py（1015 行） | 世界模型：事实+规则+地理+队列+待执行 |
| review.py（339 行） | 审查层：科技/法律/资源/上限/队列/PM/配额校验，返回通过或拒绝原因 |
| executor.py（384 行） | 执行端：dry_run / bridge（文件泵）/ mock |
| tools.py（722 行） | 给 LLM 的工具集：get_overview / query_* / calc_* / propose_* / estimate_* / build_candidates |
| llm.py | OpenAI 兼容客户端（function calling） |
| advisor_bridge.py（485 行） | 计算层能力桥接（brief/plan/市场/PM 方案） |
| web_server.py（1679 行） | 宿主编排 Web 服务与前端 |
| mcp_server.py | MCP 协议服务（外部 agent 接入） |
| host_agent.py / host/ | 宿主编排：注入 DLL、watch、启动 web（start_project.ps1） |
| strategy.py | 策略（重点产业链/禁建/预算等），对应 v3calc Intent |
| config.py / config.json | 配置（服务地址、执行端、LLM 端点） |
| cli.py / util.py / build_state_meta.py | 命令行 / 工具 / 州静态地理构建 |

**运行架构**
```
LLM（OpenAI 兼容）
   │ function calling / MCP
   ▼
AgentLoop ── Runtime.refresh() / brief() ──▶ world + v3calc.advisor
   │
   ├─ 工具循环：get_overview / query_* / calc_* / propose_*
   ├─ 审查层 review：通过→进入待执行；拒绝→返回原因
   └─ 回合末 execute_pending() ──▶ executor（dry_run/bridge/mock）
                                     │
                                     ▼
                                 v3bridge 文件泵（requests.txt 等）
```

- 一轮：refresh 快照 → 生成 brief（国家/预算/GDP/市场/信号/上轮反馈）→ LLM 查证并提议 → 审查 → 执行 → journal 记录；
- 下一轮 brief 带 execution_feedback，LLM 按真实结果修正。

## 5. v3bridge —— 执行层（DLL 注入）

> C++ / 单 DLL + 注入器　|　bridge/v3inject.dll + bridge/injector.exe　|　目标 1.15.2

**职责**：注入游戏进程，直接调用引擎的内部命令链完成建造、换生产方式、改法律等**真实操作**，并回读队列/PM 状态。不改游戏文件、不装 mod。

**文件协议**（写 txt → DLL 处理 → 改名 .done.txt → 读结果）

| 文件 | 内容 | 结果 |
|---|---|---|
| requests.txt | <州id> <建筑键> <等级> | 走引擎完整命令链建造 |
| query.txt | building <建筑键> [all] | states.csv |
| pms.txt | <州id> <建筑键> | pms.csv（激活 PM + 各组可选） |
| pmm.txt | <州id> <建筑键> <pm键> | 切换生产方式 |
| queue.txt | 任意内容 | queue.csv（建造队列） |
| pmfix.txt | <目标州> <建筑键> <参照州> [dry] | 复制完整 PM 集合 |
| bdump.txt / peek.txt / probe.on / watch.txt | 诊断用 | 内存转储 / 探针 |

**抗更新机制**：启动时校验文件指纹（大小 + FNV-1a64 哈希）；不匹配时用**签名扫描**自动重新定位函数地址、全局变量、对象虚表，日志打印 build UNKNOWN - resolving by signature，能力项自检后逐项开关。无法自动恢复的是**数据结构偏移**（CBuilding+0xF0、PM 向量、队列布局），需要实机复校。

## 11. 已知边界

- **只读原则**：v3live / v3calc 不写游戏；所有写操作只经 v3bridge（受审查层约束）。
- **GDP 口径**：绝对 GDP 只用 live + market + staffing + producers；local/all 已实测否定；存档模式只看相对排序。
- **部分均衡**：候选算账只算自己这一单对价格的影响，不重算全国反应；减产溢价封顶 1.25× 防止「少产变赚」陷阱。
- **构造性限制**：建造工期不含州效率/法令/临时修正；conditional 的 PM 需人工确认。
- **版本抗性**：桥能自动恢复函数/全局/虚表，但结构偏移是语义约定，游戏更新后需人工复校。
